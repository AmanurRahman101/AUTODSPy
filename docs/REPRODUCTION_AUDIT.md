## Findings and proposed corrections

### Policy architecture and initialization
Published: GPT-2 labeled 127M (Table 1, A.3); no custom policy head specified. Released code: pretrained GPT2LMHeadModel and GPT2Tokenizer from `gpt2`, padding=EOS. Current cells 17-18 load TinyLlama then replace it with GPT-2 and may silently reload old weights. Correction: isolated pretrained GPT-2 setup, explicit checkpoint loading only, record actual parameter count (standard tied GPT-2 is about 124M). Do not manufacture a 127M architecture. Unresolved: exact pretrained revision and experiment initialization seed are unpublished.

### Actions and pipeline termination
Published diagram/Algorithm 1 describe multiple modules and optional teleprompters; Table 1 and A.1 exclude teleprompters for main experiments. Released/current code (cell 15/20) has CoT/Predict and fifteen exact signature strings. Three decisions: module, signature, forced stop; only one executed module. Each action is scored by its first tokenizer token, with repeated token IDs intentionally repeated in the categorical action distribution. Several signatures are indistinguishable at this stage. Correction: preserve action order, strings, state prompt, duplicate IDs, and first-token scoring; accept optional trailing stop. No ReAct, tools, retrieval, new action head, full-string scoring, or teleprompter. Unresolved: diagram's richer composition is not evidenced in released GRPO code.

### GRPO objective, advantages, clipping, entropy
Published: Section 3.3 describes within-group reward normalization; Figure 2 distinguishes GRPO policy gradient from PPO clipping; A.4 Table 3 lists shared settings. Released/current `train_grpo` (cell 22) computes A_i=R_i-mean(R), and L=-sum_i sum_t log pi(a_it|state_it)*A_i. There is no division by standard deviation, probability ratio, clipping, entropy, reference model, value head, GAE, gamma, or lambda. Current baseline script adds population-std normalization but still lacks clipping; it is a later experiment.
Correction: default `notebook` objective with centered advantages and sum over group/actions. Implement differentiable sequential replay with detached behavior log probabilities; same weights during episode rollout/replay. Explicit optional `clipped` and `standardized` sensitivity modes, not silently substituted into the reproduction default. A.4 gamma=.99/lambda=.95 are metadata only; do not add GAE. Clip .2/entropy .01 apply only to the explicitly selected sensitivity objective. Equal rewards give zero advantage. Disable policy dropout for consistent replay (declared implementation assumption), not gradients. Stop is deterministic with zero log probability/entropy.

### Optimizer and learning rate
Published A.4: 1e-4. Notebook function default: Adam 1e-4; executed cells 24-25: two episodes at 2e-5/K=4, checkpoint saved under conflicting model names. Correction: Adam with PyTorch default betas/epsilon/zero weight decay, 1e-4/200 episodes/K=5; record defaults as code-derived, not paper-reported. Preserve one optimizer step per episode, average over prompt groups when extending to 200 samples; original K/action sum retained. Update cadence/aggregation for 200-sample episodes is not recoverable from the notebook.

### Dataset and sampling
Published Section 4.1: fine-tune on 200 training samples, evaluate 1,300 GSM8K test samples. A.2/A.7: 200 samples per episode; A.2 also describes 200-example pools for other tasks. Current cell 13: first ten GSM8K + first ten HotpotQA, unseeded shuffle, one randomly drawn prompt per episode; only test[:10] evaluated. Correction: official openai/gsm8k main train and test only, retain question/raw answer and canonical #### answer. Default draw 200 train indices uniformly with replacement each episode (extends released np.random.randint); no 200-unique-example cap, no HotpotQA, no test access during training. Optional fixed training pool is sensitivity configuration. Seed 42 is an assumption, not published. Log split fingerprints, selected indices and duplicate-question leakage check. Full final evaluation uses all 1,319 official test examples; paper-comparable 1,300 subset must be labeled with explicit selection seed. Exact paper indices and sampling scope unresolved.

### Execution LLM
Published A.3/Table 1: Llama 3.1 8B. Released/current cell 11: dspy.LM('ollama_chat/llama3.1:8b', localhost:11434), default provider settings. Baseline script substitutes llama3.2:3b. Correction: retain llama3.1:8b, configurable Ollama endpoint/CPU offload; preflight validates model availability and records digest, parameter size, quantization, template/parameters, version, runtime device settings. Explicit temperature, token/context limits and seed are necessary reproducibility assumptions because historical defaults were not recorded. No model substitution.

### Reward and metric
Published Section 3.3: binary reward with LLM semantic fallback; Section 4.1: exact match with LLM fallback. A.7 separately describes embedding cosine >=.92 on a 100-example subset, but does not identify embedding model. Released/current cell 20: numeric/string regex exact match then continuous [0,1] LLM partial-credit score; no actual format bonus despite docstring. Correction: retain continuous LLM reward and same judge instructions, normalize signed integers, comma-grouped numbers and decimals with Decimal; retain raw/canonical ground truths. Binary evaluation fallback uses strictly parsed 1.0/0.0, not current cell 26's unsafe `"1" in output` (accepts 0.1). Report exact-match accuracy and LLM-fallback accuracy separately, continuous training reward separately. Do not call LLM judging the A.7 embedding metric. Exact reward/metric used for 82.4% unresolved.

### Evaluation and latency
Published A.3: static Predict/CoT signature question -> answer. Current test_model ignores passed model in generation (uses global), evaluation cells 29-30 reference undefined trained_value_head and mismatched arguments; only query-mode results persisted. Correction: explicit policy objects, static Predict, static CoT, untrained saved initial weights, trained checkpoint; same test indices/instructions/LLM settings and separate seeds. Record generation, execution and judge latency separately, pipeline frequency, failure rates, total inference latency excluding judge; report timing includes warm/cold settings. Disable execution cache so repeated rollouts are real calls. No evaluation claim until completed.
