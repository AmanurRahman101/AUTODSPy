# Adaptive-K smoke verification

Date: 2026-11-01. These are engineering checks, not benchmark results.

## Changes

Both adaptive notebooks now derive their internal maximum K from `ADAPTIVE_LEVELS`. `CANDIDATE_BUDGET` optionally caps training-candidate reservations. Reservations are journaled before candidate generation; interrupted or rolled-back work remains charged. A group is only extended when the entire next level fits the remaining budget. Validation and testing calls are outside this training cap. `summary.json` reports the cap and reservation count.

The comparison path audits completed static and adaptive histories and checks dataset selections, seed, policy initialization, model/runtime, reward protocol and other training settings. Its static verifier is unchanged; the adaptive verifier validates realized K and cumulative group sizes. Runs that exhaust their candidate budget before `num_episodes` receive final validation, a durable checkpoint, and a budget-completion marker. The auditor requires journal evidence that fewer than the minimum group size remain. Use `compare_runs(paths, comparison_axis="budget", candidate_cap=N)` to compare completed runs with potentially different episode counts; it reports measured candidate use and does not claim that all runs used the full cap. For static runs, in-flight interruptions may be absent from their historical attempt journals.

## Verification

- Both notebooks' code cells parse. The mock training tests exercised boundaries with budgets 7 and 9, allowed group sizes 5 and 8, and a journal containing three interrupted reservations. They confirmed that a new minimum-size group is not started when the remaining cap is insufficient.
- A synthetic CPU checkpoint fixture exercised the notebook's checkpoint loading, restoring policy weights, Adam state, and Python, NumPy and PyTorch RNG states; a subsequent optimizer step matched the uninterrupted fixture. An incompatible rescue mode was rejected. This was not a live interrupted model run, and does not establish equivalence across all interruption points.
- GSM8K and HotpotQA real smoke records passed the adaptive artifact auditor, including validation records, checkpoint pointers, and selection manifests. Each was also compared with a derived synthetic static fixture built from its K=5 artifact. Incompatible seed and judge-seed fixtures were rejected. The static fixtures were not independently trained runs, so this checks the comparison plumbing, not scientific comparability or performance.
- GSM8K smoke: one episode, pool size 2, one validation example, five reserved candidates; Llama 3.2 3B execution and GPT-2 policy on CPU, original semantic reward, maximum execution output 128. Reported reward 0.1, gradient norm 72.6106. The stop reason was `failure_guard` after truncated responses. Run: [GSM8K summary](../results/engineering_checks/adaptive_smoke/gsm8k/adaptive-both/seed42/baseline/20261101T134252-7018c826/summary.json).
- HotpotQA smoke: one episode, pool size 2, one validation example, five reserved candidates; same CPU models, `answer_exact` reward, maximum execution output 32. Reported reward 0.2, gradient norm 251.9856. The stop reason was `failure_guard` after truncated responses. Run: [HotpotQA summary](../results/engineering_checks/adaptive_smoke/hotpotqa/adaptive-both/seed42/baseline/20261101T134737-7932cd1e/summary.json).
- The HotpotQA initial configuration failed because inherited K=5 conflicted with the default adaptive levels. The configuration was corrected and the smoke rerun successfully. No model inference occurred in the failed initialization.
- Required AST-only `graphify update .` ran; the extractor reports that it skips notebooks, so its graph is not validation of notebook contents.

Both initial live runs used intentionally small output limits and returned truncation warnings. They exercised only K=5 and the failure guard; neither established held-out test behavior, interrupted live recovery, or equal-budget research performance. No full training was launched. An independent matching static run remains necessary before drawing a research comparison.

## Follow-up checks

- A controlled synthetic fixture ran the notebook's training loop twice, injected an interruption in episode 2, restored its actual checkpoint, and resumed. For both datasets, resumed final model weights matched the uninterrupted fixture, two updates were completed, and the journal charged the two interrupted candidate reservations. External model execution and reward functions in this check were mocks.
- A budget-finished adaptive artifact fixture passed the early-stop audit, and a modified reservation count was rejected. A comparison between this fixture and a derived static fixture passed in budget mode with a shared cap of seven; the episode-axis comparison rejected their differing configured horizons. Separate fixtures checked a cap of five and rejected a cap of four. These are plumbing checks rather than independently trained research comparisons.
- A live GSM8K extension fixture used CPU GPT-2, local Llama 3.2 1B, numeric-exact rewards and a budget of eight. It deliberately restricted the action space to one `Predict`/`question -> answer` pipeline to obtain repeatable real executions. Five successful zero-reward candidates caused extension to K=8; all eight were executed and journaled, and the group stopped at the budget. The gradient was zero in this single-choice fixture. Its narrowed action space was injected by the smoke driver and is not represented in the run's normal configuration metadata: **do not use this run in research comparisons**. Its saved history passed the adaptive artifact audit. [Extension smoke summary](../results/engineering_checks/adaptive_smoke/gsm8k/adaptive-both/seed42/baseline/20261101T141613-e6cce9dc/summary.json).
- An earlier extension attempt using the regular action space stopped at K=5 on `failure_guard`; it did not exercise extension.
