# Domain docs

## Layout and reading rules

This repo uses a single-context layout:

- GLOSSARY.md at the repository root defines domain terms.
- docs/adr/ holds architecture decision records.

Before exploring a domain area, read the glossary and relevant ADRs
when present. If absent, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Existing research documents remain in their current locations and
retain their stated authority.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the terminology or record
the gap for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that conflicts with an existing ADR
and explain why the decision should be reconsidered.
